# lefthook Type Check Fix

## Problem

lefthook was running type-check on **entire monorepo** even when no TypeScript files were staged:

```yaml
# BEFORE (wrong)
type-check:
  run: pnpm turbo run type-check  # ❌ Always runs, checks everything
```

**Issues**:
1. ❌ Runs even when no .ts files staged (e.g., only markdown changed)
2. ❌ Finds errors in files you didn't touch
3. ❌ Blocks commits for pre-existing errors
4. ❌ Slow (checks entire monorepo)

---

## Solution

Use the **canonical lefthook + Turborepo pattern**:

```yaml
# AFTER (correct)
type-check:
  glob: "*.{ts,tsx,mts,cts}"           # ✅ Only run if .ts files staged
  run: pnpm turbo run type-check --filter="[HEAD]"  # ✅ Only check changed packages
```

**Benefits**:
1. ✅ **Skips when irrelevant** - No .ts files staged? No type check runs
2. ✅ **Only checks what changed** - Turborepo filter finds affected packages
3. ✅ **Fast** - Doesn't check unrelated packages
4. ✅ **Focused** - Only fails on errors in YOUR changes

---

## How It Works

### The `glob` Filter

```yaml
glob: "*.{ts,tsx,mts,cts}"
```

**Effect**: Type-check **only runs** if staged files match this pattern

**Examples**:
```bash
# Staged: README.md, package.json
# Result: Type check SKIPPED ✅

# Staged: apps/web/src/main.tsx
# Result: Type check RUNS ✅

# Staged: docs/guide.md, apps/web/src/user.tsx
# Result: Type check RUNS (found .tsx) ✅
```

### The Turborepo Filter

```yaml
run: pnpm turbo run type-check --filter="[HEAD]"
```

**Effect**: Only type-check packages with **staged changes**

**How it works**:
- `[HEAD]` - Git ref-based filter
- Turborepo finds packages with changes since HEAD
- Runs type-check ONLY for those packages

**Examples**:
```bash
# Staged: apps/web/src/main.tsx
# Runs: pnpm turbo run type-check --filter="[HEAD]"
# Checks: apps/web (only)
# Skips: All other 30+ packages ✅

# Staged: packages/ui/src/button.tsx, packages/db/src/client.ts
# Checks: packages/ui, packages/db (only)
# Skips: All other packages ✅
```

## Canonical Pattern Explanation

### Why This Is Idiomatic

This follows **official lefthook + Turborepo best practices**:

**From lefthook docs**:
```yaml
# Run commands only when relevant files are staged
command:
  glob: "*.{ts,tsx}"  # Only run if TypeScript staged
  run: your-command {staged_files}
```

**From Turborepo docs**:
```bash
# Check only changed packages
turbo run type-check --filter="[HEAD]"

# Or check packages that depend on changed packages
turbo run type-check --filter="...[HEAD]"
```

**Combined**:
```yaml
type-check:
  glob: "*.{ts,tsx,mts,cts}"  # Only if TypeScript staged
  run: pnpm turbo run type-check --filter="[HEAD]"  # Only changed packages
```

**Result**: Fast, focused, idiomatic validation ✅

## Alternative Patterns

### Option 1: Current (Recommended)

```yaml
type-check:
  glob: "*.{ts,tsx,mts,cts}"
  run: pnpm turbo run type-check --filter="[HEAD]"
```

**Pros**: Fast, focused, only checks your changes  
**Cons**: Doesn't catch cross-package breaking changes  

### Option 2: Check Changed + Dependents

```yaml
type-check:
  glob: "*.{ts,tsx,mts,cts}"
  run: pnpm turbo run type-check --filter="...[HEAD]"
```

**Pros**: Catches breaking changes in dependent packages  
**Cons**: Slower (checks more packages)  

### Option 3: Full Monorepo (What You Had)

```yaml
type-check:
  run: pnpm turbo run type-check
```

**Pros**: Most comprehensive  
**Cons**: Slow, blocks on pre-existing errors, frustrating  

### Option 4: Skip Pre-Commit, Rely on Hooks

```yaml
# Remove type-check from pre-commit entirely
# Rely on Claude Code hooks + CI/CD
```

**Pros**: Fastest commits  
**Cons**: Manual commits bypass Claude hooks  

---

## Recommended: Option 1 (Current)

**Why**:
- ✅ **Smart filtering** - Only runs when TypeScript staged
- ✅ **Fast** - Checks only affected packages
- ✅ **Reasonable** - Only blocks on YOUR errors
- ✅ **Idiomatic** - Standard Turborepo pattern
- ✅ **Turborepo caching** - Even faster on subsequent runs

**When it blocks** (correctly):
- You stage a .ts file with type errors
- You stage a .ts file that breaks types in that package

**When it doesn't block** (correctly):
- No .ts files staged
- Staged .ts files have no type errors
- Pre-existing errors in other packages

## Complete Hook Flow

### Scenario 1: Markdown-Only Commit

```bash
git add README.md
git commit -m "Update docs"

lefthook:
  ✓ Biome check (runs on README.md)
  ⏭️  Type check SKIPPED (no .ts files)

Commit: ✅ SUCCEEDS
```

### Scenario 2: TypeScript File With Errors

```bash
# Edit apps/web/src/user.tsx (introduce type error)
git add apps/web/src/user.tsx
git commit -m "Update user component"

lefthook:
  ✓ Biome check (formats user.tsx)
  🔍 Type check (checks apps/web only)
  ❌ FAILS - type error in user.tsx

Commit: ❌ BLOCKED
→ Fix error
→ Try again
```

### Scenario 3: TypeScript File Without Errors

```bash
git add apps/web/src/main.tsx
git commit -m "Add comment"

lefthook:
  ✓ Biome check
  ✓ Type check apps/web
    (uses cache, instant!)

Commit: ✅ SUCCEEDS
```

### Scenario 4: Pre-Existing Errors Elsewhere

```bash
# packages/test-utils has type errors
# But you're editing apps/web

git add apps/web/src/main.tsx
git commit -m "Update main"

lefthook:
  ✓ Biome check
  ✓ Type check apps/web (only)
  ⏭️  Skips packages/test-utils

Commit: ✅ SUCCEEDS ← This is correct!
```
