🚨 Severity: CRITICAL
💡 Vulnerability: API Key length leaking via timing attack. The `queue-telemetry-collector` returned early during validation if the provided HMAC length didn't match the expected length, allowing an attacker to determine the hash length via timing differences.
🎯 Impact: Attackers can discover the length of the valid HMAC. While less exploitable for fixed-length hashes like SHA256, it violates constant-time comparison principles and can also cause a DoS if `timingSafeEqual` is reached with mismatched lengths.
🔧 Fix: Ensure `timingSafeEqual` runs in constant time regardless of length match by executing a dummy check when lengths differ.
✅ Verification: Ran `pnpm --filter @brainstrike/queue-telemetry-collector test` to ensure tests passed and functionality remains the same.
