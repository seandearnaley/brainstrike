## PHASE 1 Handoff – Mastra Agent Foundation

Date: 2025-09-13
Owner: Core Platform (Brainstrike)
Scope: Shared agent foundation + initial web plumbing

### Context (read me first)
- We are implementing a Mastra-based, multi-step reasoning chat agent for both web and desktop.
- This handoff covers Phase 1 only. Phase 2 will wire a real chat UI to the new `/api/chat` route.
- The repo is a Turborepo monorepo with strict TypeScript, React 19, Tailwind v4, and shadcn/ui.

### What changed in this phase
- Created `@brainstrike/agent` package with:
  - Typed stream API (`AgentMessage`, `StreamChunk`) and a dev `createDevChatAgent()` wrapper.
  - Initial streaming path now superseded by Mastra runtime (`streamMastraAgent`).
  - Minimal in-memory conversation store for early development.
  - Deps added for forward compatibility: `@mastra/core`, `@ai-sdk/openai`, `ai`.
- Web: added a streaming API route and a UI placeholder
  - `apps/web/src/app/api/chat/route.ts`: streams newline-delimited JSON chunks from the agent.
- Historical note: `ChatPanelStub` was initially added under Props; update 2025‑09‑15 — assistant‑ui replaced ChatPanel in the right panel.
- TypeScript project references
  - Root `tsconfig.json`: path mapping for `@brainstrike/agent`.
  - `apps/web/tsconfig.json`: path mapping + reference + `baseUrl`.
  - `packages/agent/tsconfig.json`: `composite: true` enabled.

### Why we made these choices
- The dev agent and workflow provide a working, typed stream with minimal dependencies so Phase 2 UI work can proceed without waiting on provider keys.
- Using newline-delimited JSON from the route keeps the transport simple; we can swap to AI SDK data streams easily later.
- The Props tab stub lets us integrate the chat panel into the existing right-panel layout without breaking state-preservation patterns.
