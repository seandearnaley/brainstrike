Explorer Resize Thrash Analysis

Date: 2026-05-17. Branch: codex/explorer-resize-thrash-analysis.

Static analysis does not support the idea that restored expansion state bypasses the virtualized DOM window. The failure mode is earlier in the pipeline: restored expansion state makes the explorer materialize a large visible-row model before the virtualizer can constrain rendering.

Current Read

The File/Workspace Explorer left panel restores expanded directory paths from the persisted Zustand store, then loads those paths, commits the restored set back to the store, builds a complete list of visible tree rows, and finally passes that complete list into TreeTable with windowingStrategy="virtual".

That means virtualization limits DOM rows, but it does not limit the upstream row model, ARIA metadata, lookup maps, or keyboard-navigation model. A restored expanded tree therefore has a much larger main-thread surface than a manually expanded session with only a few open branches.

Evidence

Hydration

hydrateFolderState() recreates expandedDirectoryPaths from the persisted per-folder state as a new Set.

File: packages/file-explorer/src/actions/folder-state-actions.ts:142-159.

Path Restoration

useExpandedPathRestoration() combines persisted expanded paths, selected file parents, and query-covered directories, sorts the full set, loads paths, then writes a merged expanded set back to Zustand.

File: packages/file-explorer-ui/src/use-expanded-path-restoration.ts:176-188, :248-263, :382-402.

Pre-Virtualization Rows

OptimizedFileTree subscribes to the expanded set and builds treeRows for every visible expanded node before rendering TreeTable.

File: packages/file-explorer-ui/src/optimized-file-tree.tsx:1981-2088, :2495-2510.

TreeTable Work

Even with virtualization, TreeTable flattens the full provided row list, builds an indexMap, and builds a nodeById map over all nodes.

File: packages/ui/src/tree-table/tree-table.tsx:518-569, :598-605.

Resize Path

The panel resize layer is not obviously the primary bug. IdeLayout already coalesces layout changes with requestAnimationFrame, defers persisted layout writes during drag, and gates collapse handlers so they only fire when the collapsed boolean changes.

Files: packages/ui/src/layout/ide-layout.tsx:125-230, :1285-1291.

TreeTable also overrides TanStack Virtual's container rect observer so width-only changes during horizontal resize do not call the virtualizer callback. This was explicitly added to avoid full React re-render per frame during horizontal panel resize.

File: packages/ui/src/tree-table/tree-table.tsx:698-725.

Likely Root Cause

The root cause is not DOM bloat from rendering all expanded rows. It is restored expansion turning the tree into a large visible-row data set, then doing O(visible rows) work before and around virtualization. During resize, any remaining render, measurement, or layout invalidation now operates with that large model in memory and on the call stack.

The high-risk operations are:

  • Recreating large Sets during store merge/hydrate: state-serialization.ts:254-309 and folder-state-actions.ts:142-159.
  • Sorting and loading the entire restored path set: use-expanded-path-restoration.ts:382-402.
  • Building treeRows for every visible expanded node: optimized-file-tree.tsx:2062-2088.
  • Duplicating that full row model inside TreeTable: tree-table.tsx:518-569.
  • Measuring visible rows through rowVirtualizer.measureElement, which can still run during width-driven layout changes: tree-table.tsx:831-852.

Architecture Implication

A narrow debounce around hydration would be a symptom fix. The more durable direction is to make virtualization own the row model boundary: avoid passing a complete expanded visible-row array into TreeTable when the left explorer is large, or give TreeTable a pre-flattened fast path that trusts already-flattened row metadata instead of rebuilding it.

A second useful direction is to make restored expansion incremental: commit a bounded first window and progressively load/expand deeper paths without forcing the first interactive resize to carry the full restored tree.
