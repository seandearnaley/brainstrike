## 2024-05-18 - Prevent Timing Attacks in API Key Validation
**Vulnerability:** The API key validation used standard string equality (`===`) to compare the expected API key with the provided key. This exposes the application to timing attacks where an attacker can slowly deduce the secret by measuring the time it takes the server to reject incorrect characters due to early-exit string comparisons.
**Learning:** `timingSafeEqual` from `node:crypto` is necessary for secret comparisons but it has a strict constraint: it throws an error if the two `Buffer`s provided are of unequal lengths. To achieve constant time for inputs of varying lengths without leaking information or throwing, you must structure the condition to compare valid buffers (e.g., comparing the expected buffer against itself) even when the lengths mismatch, before ultimately failing the overall check.
**Prevention:** Always use `crypto.timingSafeEqual` for validating secrets. Pad or conditionally swap the compared buffers to ensure `timingSafeEqual` always runs on equal-length inputs to prevent unhandled runtime errors, while ensuring the authentication fails securely.
