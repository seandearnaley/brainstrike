Flight
Recorder

Durable error observability for BrainStrike threads, and a one-click debug bundle any LLM agent can fix from.

Thread trace · run 7f3a · openrouter/qwen3-coder

Flight recorders are painted international orange so they can be found after the incident. That is the whole design: when a thread goes down, the evidence must already be on disk. Findable, structured, and complete enough that nobody has to crash the plane again to learn what happened.

CH·01 · Why now

The problem

Model coverage is growing faster than our ability to explain failures.

Every new provider and model multiplies the failure surface: context-length rejections, rate limits, mid-stream resets, tool-argument stalls, prefill quirks. Today a failed thread leaves behind one free-text error string and a console log that evaporates when the window closes. Diagnosing means re-running — again and again — hoping the failure reproduces.

  • Errors in threads are visible for a moment, then unqueryable forever.
  • Background failures (hidden hosts, embedding queue, renderer crashes) are invisible unless you were watching the console at the right second.
  • Agents can't help without evidence: neither the in-app assistant nor an external Claude Code session can see what already went wrong.
GOAL // When a thread fails: press one button, get a complete, bounded, redacted Markdown bundle; paste it into an agent; get a fix. And for everything else: a durable warn+ record that survives closing the app.

CH·04 · Options

Three approaches

A · DB-first + file mirror

New PGlite table for warn+ events from every process; desktop mirrors to a rotating NDJSON file.

Queryable (SQL, live queries, fingerprint grouping), identical on web, plays to "the database is the moat." The file covers the one failure the DB sink can't record: a broken database.

✔ RECOMMENDED

B · File-first only

Structured rotating log files, no table.

Simplest, but web gets nothing durable, nothing is queryable, no grouping or trends, and bundle assembly means parsing text back apart.

✕ Rejected as primary · kept as A's desktop mirror

C · Extend run_events

Widen the existing assistant timeline into the app-wide store.

Run-scoped by schema, its sanitizer strips bodies by contract, and its retention is conversation-lifetime. Wedging app-wide warnings in muddies a settled contract.

✕ Rejected: scope is "do not relitigate"

CH·05 · System

Architecture

Capture → sinks → consumers

One capture seam (the existing addLogListener fan-out), so no second event API. Renderers write via the DB bridge; hidden hosts and main reuse the existing log-forwarding IPC. The writer never blocks the stream path: capture is listener-side, writes are batched and unawaited.

CH·06 · Storage

The durable store

CREATE TABLE brainstrike_diagnostic_events (
  id UUID PRIMARY KEY,               -- uuidv7, time-ordered
  occurred_at TIMESTAMPTZ, severity TEXT,   -- warn | error | fatal
  source TEXT,                       -- electron-main | desktop-renderer | web-renderer | *-host | db-worker
  scope TEXT, code TEXT,             -- logger scope + stable machine code
  message TEXT, stack TEXT,          -- bounded, visible truncation markers
  cause_chain JSONB, context JSONB,  -- walked Error.cause · redacted metadata
  fingerprint TEXT,                  -- md5(code|scope|normalized msg) → grouping is GROUP BY
  session_id TEXT,                   -- per-launch uuid, stitches processes
  run_id TEXT, thread_id TEXT, resource_id TEXT, root_id TEXT,
  app_version TEXT, platform TEXT )

Writer semantics — the honest parts

  • Loud loss. Overflow drops oldest and emits a diagnostics_events_dropped count on the next flush. We never silently lose loss.
  • Loop guard. DB-layer errors route only to file/console; N failed flushes disable the DB sink for the session with a visible banner. Degradation, never recursion.
  • Corruption-safe. The writer honors the DB-recovery generation; the corruption error itself lands in the file mirror, which is exactly why the mirror exists.
  • Retention. Bounded oldest-first purge: 30 days / 20k rows (settings-configurable). Factory reset wired; both migration runners; lane manifest.
  • Close-safe. Flush on visibilitychange:hidden / graceful shutdown: the "survives closing this out" guarantee.
CH·07 · Headline feature

The debug bundle

One button on the failed message: Copy debug bundle. One Markdown document. Everything an agent needs, nothing it shouldn't see.

§SectionSource
1Failure summary — code, message, cause chain, provider/model, timingsthread_runs + run_errors NEW
2Run configuration — settings, options, enabled tools, MCP servers (names)thread_runs
3Run timeline — ordered events with durationsrun_events
4Resilience history — every retry, classification, backoffrun_errors.attempts NEW
5Correlated diagnostics — warn+ events around the failure (±5 min)diagnostic_events NEW
6Transcript — bounded, redacted, tool args/results includedmastra_messages
7Usage & costrun_usage
8Environment — versions, OS, DB diagnostics, crash snapshotdiagnostics IPC
9Prior related failures — same fingerprint, 7 days, first/last seendiagnostic_events NEW

Bounded and deterministic: 200 KB target; over budget, elide old transcript turns first (keep the failing turn ± 2), then tool bodies, then timeline detail. Every cut leaves a visible marker. Redaction runs at capture and again over the assembled bundle.

Why it ends the re-run loop: sections 4, 5 and 9 don't exist anywhere today at any price. They record what the retry layer already tried, what else was failing at that moment, and whether this is the 1st or 14th occurrence. Sections 1–3 + 6 mean the agent doesn't even need the app open.

Copy uses the existing clipboard bridge; Save… reuses the log-destination picker; web copies via navigator.clipboard and downloads a Blob. Bundle is versioned (bundle_format: 1).

CH·08 · Multi-provider

Provider forensics

The highest-leverage schema change for the many-models problem: a FK-less sibling table written once per failed run at the existing terminal choke points.

brainstrike_assistant_run_errors
  run_id PK · code · message · cause_chain
  http_status · provider_request_id          -- x-request-id, when present
  response_headers JSONB                     -- WHITELISTED: ratelimit-*, retry-after
  attempts JSONB  -- [{n, at, classification, waitedMs}] from the retry stack

Headers come from a per-provider fetch wrapper (the prompt-caching wrapper shows this is already idiomatic in the provider factory). Only the whitelist is stored; bodies never are. thread_runs.error stays for back-compat; the error block in the UI gains "code + request-id" with a copy affordance — because every provider support ticket starts with "what's the request id?"

CH·09 · Platforms

Desktop text log · web variant

Desktop

${logs}/brainstrike-errors.ndjson — warn+, size-rotated (10 MB × 5). All processes land here via the existing forwarding IPC.

Line shape = table row shape: a grep hit and a SQL row are the same object. External agents get jq-able structure without launching the app.

brainstrike.log (full INFO) finally gets rotation too.

Web

Same PGlite table — the durable story is identical because the database travels with the browser profile.

No file system, honestly: the equivalent is Export errors (NDJSON) in the Log Viewer, generated from the table in the same line format.

Close-safety via flush on visibilitychange:hidden.

CH·10 · Self-service

Agents diagnose without re-running

  • In-app assistant: new read-risk native tool brainstrike.queryDiagnostics, filtering by severity, time window, thread, code, fingerprint. "Why did my last run fail?" becomes a DB read, not a reproduction.
  • External agents (Claude Code et al.): the NDJSON file, greppable with zero app involvement.
  • You: Log Viewer gains a "Persistent errors" source (the viewer's adapter contract already supports plugging one in) plus a status-bar chip counting unseen warn+ events, so background failures become visible instead of invisible.

Follow-up, out of scope: exposing the same query via the Agent Hub MCP server (#1187).

CH·12 · Needs you

Five decisions

1 · Retention defaults?
PROPOSED: 30 days / 20,000 rows, both configurable in settings.
2 · Severity floor for the durable store?
PROPOSED: warn+. Option: opt-in INFO for specific scopes (e.g. provider requests).
3 · Bundle privacy: include transcript text + tool args by default?
PROPOSED: yes, redacted. Optional "metadata-only" variant for sharing off-machine.
4 · Table name?
PROPOSED: brainstrike_diagnostic_events (it stores warnings, not just errors).
5 · Phase order?
PROPOSED: P1 → P4a → P3 → P4b → P2 → P5 if the copy button is the priority.
