Actions budget policy - 2026-05-24

Release proof is explicit. Accidental manual runs are cheap.

Brainstrike now treats the full release matrix as an intentional proof, not a default side effect. Nightly still runs the matrix automatically. Manual runs must opt in with release_proof=full-release. A plain manual dispatch defaults to release_proof=skip and does not run static checks, builds, coverage, or E2E.

Default manual dispatch
Skip

Records the selected policy and exits cheaply. This is deliberate protection against accidental matrix spend.

Nightly release proof
Full

Runs the complete release matrix on the scheduled workflow. No human input required.

Manual full proof
Opt-in

Requires release_proof=full-release and should include a reason.

When To Run What

SituationRunExpected CostWhy
Normal small PR PR selected lanes only Low to medium ci:select and the proof manifest choose the risk-owned cloud lanes.
Merge to main Main push smoke gate Bounded Static checks plus web and desktop smoke prove the branch did not immediately break app startup.
Routine release confidence Nightly schedule High, planned The full matrix runs once per day instead of after every merge.
Release-risk merge before the next nightly Manual release_proof=full-release High, intentional Use only when waiting for nightly would create unacceptable release risk.
Desktop backgrounding investigation Manual release_proof=desktop-backgrounding Medium Runs the targeted manual diagnostic without paying for the full release matrix.

Manual Full Release Proof Steps

Open the Test workflow in GitHub Actions.
Choose Run workflow on the target branch.
Set release_proof to full-release.
Enter a concrete reason, such as release candidate before tag or high-risk desktop runtime merge.
Wait for Required Release Gate. It is the release proof verdict.
Do not use manual full release proof as a normal PR feedback loop. If a PR needs a lane, fix ci:select or the PR labels. If a PR needs the whole matrix, label it ci:full and treat it as high-risk.
