Phase 2 stacked PR artifact - 2026-05-19

Platform contracts before workflow moves.

This phase starts the desktop platform reset without touching the high-risk DB, file, embedding, or assistant bridges. The first production migration is the logging bridge: typed channel constants and runtime validators in Electron main, mirrored constants in the sandboxed preload, and guardrails that keep local model execution in renderer hosts.

Branch: codex/domain-reset-phase-2-platform-contracts Base: codex/domain-reset-phase-1-guardrails Risk: Low/medium First bridge: logging

Why Now

The reset needs deterministic platform seams before feature domains move. Without typed bridge contracts, every later package split risks duplicating channel strings, request validation, and host lifecycle assumptions.

Scope

Keep the slice intentionally small: logging IPC only, runtime-host import guardrails, and documentation. No DB, file, embedding, LLM, assistant, or MCP bridge migration in this PR.

Non-negotiable

Sandboxed preload remains self-contained. It cannot import local helper modules at runtime, so the main contract and preload constants are kept in parity through tests rather than a runtime import.

Logging Bridge Migration

Before

  • Raw channel strings repeated in logging-ipc.ts and preload.
  • set-preferences trusted TypeScript types across an IPC boundary.
  • Invalid renderer payloads could reach mutable logging state.
->

After

  • platform/logging-api-contract.ts owns canonical main channels.
  • Runtime validators reject malformed preferences and destination targets.
  • Preload uses named mirrored constants and stays sandbox-compatible.

Runtime Hosts

platform/runtime-host-boundary.ts scans desktop source with the TypeScript parser. It allows renderer host imports and type-only shared contracts, but rejects executable Electron-main imports from @brainstrike/agent/local-llm and @brainstrike/embeddings/worker.

Forward Path

Later Phase 2 or Phase 3 PRs can move higher-risk bridges only after this contract shape proves stable. The next candidates are lifecycle/channel contracts for parser, embedding-host, chunking-host, and LLM-host because they already share request, progress, status, and cancellation patterns.
