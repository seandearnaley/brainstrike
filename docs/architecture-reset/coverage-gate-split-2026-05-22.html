Coverage Gate Split

Corrective change for the 31 minute PR unit gate. The previous label model made ordinary source changes pay for full affected coverage plus serial DB coverage. This split makes routine PRs run affected unit tests, while DB/full coverage becomes explicit risk.

branch: codex/split-coverage-gate · date: 2026-05-22

Observed Failure

31m16s

Checks (unit-coverage) on PR #1031 dominated total PR wall time.

Root Cause

1 label

ci:coverage was selected for almost every non-doc source change.

Correction

3 lanes

ci:unit, ci:coverage-db, and ci:coverage-full now separate routine unit risk from heavy coverage risk.

New Gate Model

Lane Workflow Job Selection Rule Expected Effect
ci:unit Checks (unit-affected) Normal app/package source changes, isolated unit-test changes, product lanes. Runs Turbo affected unit tests only. No coverage and no serial DB coverage.
ci:coverage-db Checks (coverage-db/full) DB, storage, file-system, web DB startup/reset, desktop DB-storage changes. Keeps DB coverage explicit for data-platform risk.
ci:coverage-full Checks (coverage-db/full) Coverage infrastructure changes. Runs the heavy coverage path only when coverage tooling itself changes.
ci:full All release-risk jobs Workflow/package-manager/build-tool changes. Preserves full release confidence.
There is no hidden fallback from ci:unit to coverage. The Required PR Gate maps selected labels directly to the owning job: ci:unit → unit_affected, ci:coverage-db → unit_coverage, ci:coverage-full → unit_coverage.
