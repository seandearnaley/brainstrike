01 / Current Assessment

Where We Are

Overall status: architecture reset foundation is credible, but not yet complete product architecture. The branch has reduced cross-domain ambiguity and proved the app can still pass a full local suite. The next phase should be smaller, measurable, and ruthless about separating product architecture from pipeline economics.

What is now materially better

  • Domain boundaries are not theoretical anymore. Current guard checks pass with 0/0 approved exceptions.
  • Assistant contracts moved out of app-shell/UI/runtime coupling and into @brainstrike/assistant-contract.
  • Indexing contracts exist as a first-class package instead of being spread across queue, preferences, embeddings, and import code.
  • File explorer has internal domain slices: tree, preview, indexing, and shell.
  • Desktop platform validation was centralized for logging, preload, and runtime host surfaces.

What is still not good enough

  • The pipeline is still too expensive to use casually. The full local E2E run took 24m21.731s.
  • Top hotspot files remain large: embedding-worker-renderer.test.ts is 8,125 lines and embedding-worker.ts is 2,778 lines.
  • The file explorer split is internal, not a true workspace/package split yet. That is correct sequencing, but not the finish line.
  • The latest full green suite was on f723a86c6. Current HEAD is badd03ecb, a turbo config-only commit that has current architecture guards but not a repeated full E2E proof.
  • turbo.jsonc now uses concurrency 40. That may be faster or it may oversubscribe local/CI runners. It needs timing evidence, not belief.

Correct strategic direction

Keep the local-only flow for this reset until the branch is coherent. Do not reopen the stacked PR process for architecture experimentation. The right order is local proof, report, targeted commits, then one deliberately scoped integration path.

Main risk

The project can regress into spending cycles on proof mechanics instead of product architecture. The way out is to set measurable goals, attach a command/evidence set to each, and refuse to call work complete unless the exit conditions are met.

05 / Top 3 Goals

Three Achievable, Measurable Goals

These are the three goals I would use to get Brainstrike where it needs to be: efficient pipelines, deterministic architecture, and a runtime platform that can carry the next one to two years of local-first AI features.

01

Make the pipeline risk-based, timed, and boring

highest ROI
4-6 focused days

Why this matters

The app is now large enough that "run everything" is not a workflow. The full E2E suite works, but it is too expensive as the default loop. The pipeline should prove exactly the risk introduced by a change, then reserve full expensive lanes for nightly, release, or explicit high-risk work.

Implementation shape

  • Turn ci:select into the source of truth for local and cloud lane selection.
  • Split E2E into critical smoke, stateful product, desktop embedding diagnostics, and long soak lanes.
  • Add machine-readable timing budgets from ci:timing-summary.
  • Benchmark turbo.jsonc concurrency values instead of guessing.
  • Make "full suite" a scheduled/release proof, not the normal feedback path.

Conditions for done

  1. For 10 representative changes, pnpm ci:select --base origin/main --head HEAD chooses the same lanes locally and in CI.
  2. Median local PR-risk proof is under 8 minutes; p95 is under 15 minutes on the target Mac runner.
  3. Critical PR cloud gate is under 12 minutes p95 for non-E2E changes and under 20 minutes p95 for normal UI/product changes.
  4. Full local suite remains green and documented, but runs only on explicit full-risk, nightly, or release paths.
  5. No PR/check failure for missing proof label, stale proof manifest, or wrong lane selection for 30 consecutive PRs.
  6. turbo.jsonc concurrency has measured results for at least 16, 24, 32, and 40, with the chosen value documented.
02

Finish domain ownership by reducing hotspot size and cross-domain churn

architecture core
2-3 weeks

Why this matters

The boundary checker says imports are legal, but size and churn still show where humans and agents will collide. To make agent work parallel and deterministic, the hot files need to become thin composition points over well-owned modules.

Implementation shape

  • Promote file-explorer internal slices into enforced public barrels first, new packages only after import pressure justifies it.
  • Split embedding-worker.ts by lifecycle, scheduling, provider execution, telemetry, and host messaging.
  • Split the 8,125-line desktop embedding E2E file into focused smoke, regression, memory diagnostic, and long-soak specs.
  • Decompose packages/db internally around queue, migrations, repositories, search, and schema surfaces.
  • Add package-local architecture tests for each domain that owns public barrels.

Conditions for done

  1. No source file over 1,500 LOC except generated or explicitly documented fixture files.
  2. No test file over 2,000 LOC; long desktop embedding diagnostics are split by purpose and lane tag.
  3. file-explorer-left-panel.tsx, assistant-ui-panel-wrapper.tsx, ipc-handlers.ts, and embedding-worker.ts each lose at least 40 percent LOC or become pure composition/registry modules.
  4. Top 10 six-month churn files have an owning domain README and a focused test command.
  5. Domain boundary checks still pass with 0/0 exceptions after the splits.
  6. New feature work can be assigned to non-overlapping write sets for file explorer, assistant, indexing, desktop platform, and db surfaces.
03

Turn desktop runtime, indexing, and local AI hosts into a platform

next-year readiness
3-5 weeks

Why this matters

Brainstrike is local-first, AI-native, and web-second. The next one to two years will add more local models, more indexing paths, more background work, and more desktop reliability pressure. That cannot sit in ad hoc Electron IPC and monolithic workers.

Implementation shape

  • Create a typed desktop IPC registry with domain modules for db, files, embeddings, LLM host, preferences, and diagnostics.
  • Keep renderer-only contracts enforceable for local LLM and embedding execution.
  • Move indexing orchestration toward @brainstrike/pipeline or delete that package if it is not the owner.
  • Add host lifecycle state machines for hidden embedding and LLM renderers.
  • Make reset, migration, telemetry, and crash recovery observable from one diagnostics surface.

Conditions for done

  1. apps/desktop/src/ipc-handlers.ts is under 500 LOC and delegates to typed domain registries.
  2. Adding an IPC channel requires one contract definition, one handler, and one test. No manual preload/main/renderer triple drift.
  3. Architecture guards fail if local LLM or embedding workers are imported into Electron main process execution paths.
  4. @brainstrike/pipeline has a real inbound production consumer or is removed from the workspace graph.
  5. Factory reset E2E proves DB, UI persistence, IndexedDB, CacheStorage, and host runtime state all return to first-run behavior.
  6. Desktop crash/restart tests prove hidden host recovery without visible renderer reload for indexing and local LLM paths.
06 / Execution

Recommended Sequence

This order keeps costs controlled. First make the feedback loop cheaper, then finish decomposition, then harden the runtime platform.

Week 1

Measure pipeline lanes and concurrency. Produce timing table for 16/24/32/40 concurrency. Lock lane taxonomy and budgets.

Weeks 2-3

Reduce hotspots: split embedding E2E file, split worker internals, enforce file-explorer public barrels, shrink shell files.

Weeks 4-6

Desktop IPC registry and host lifecycle contracts. Move pipeline ownership decision from report to code.

Weeks 7-8

Full local proof, targeted manual QA, update architecture docs, then decide integration path with one coherent branch.
