01 / Summary

The ELI15 Version

Before the reset, Brainstrike had grown the way real apps grow: features worked, but many important changes touched too many files, tests were expensive, and desktop runtime behavior lived in several places at once. The reset made ownership explicit.

Before: everyone walked through everyone else's room

A file explorer change could touch UI, context, indexing hooks, and app shell. A desktop IPC change could require manually keeping main, preload, renderer, and tests in sync. A normal PR could end up paying for broad coverage or broad E2E because the pipeline did not know the difference between small risk and release risk.

After: each room has a front desk

Assistant, indexing, file explorer, DB, desktop platform, and proof lanes now have clearer public surfaces. Code should talk through contracts and barrels instead of deep internal imports. The pipeline classifies the changed files, picks lanes, records proof, and makes failures point at an owner.

Think of domains as school departments

Math, science, and history can share a building, but each department owns its curriculum. In Brainstrike, packages like assistant-contract and indexing-contract define the curriculum.

Think of IPC as a switchboard

Desktop calls now go through named domain registries instead of one giant pile of handlers. Adding a channel should mean contract, handler, and focused test.

Think of CI as airport security

A backpack should not go through cargo inspection. The new lane system routes small changes through smaller checks and keeps full release proof explicit.

02 / Why

What Problem The Rewrite Solved

The old architecture was not "bad"; it was overloaded. The app had accumulated local AI, Electron hidden hosts, file indexing, PGlite storage, assistant UI, and large E2E coverage. Those systems need strong ownership because timing and state bugs are expensive.

  • 1
    Parallel work was risky.

    Hot files and deep imports meant two agents could easily edit the same composition points or rely on internals from another domain.

  • 2
    Desktop runtime behavior was too implicit.

    Electron main, preload, renderer, hidden embedding host, hidden LLM host, DB host, reset, and diagnostics all need clear contracts because ordering failures can look like random flakes.

  • 3
    Proof cost was not proportional to risk.

    The goal became: do not use full E2E or full coverage as the default loop. Pick the lane that matches the changed files, and make the full suite a deliberate release action.

  • 4
    CI failures needed ownership.

    A failure should say "desktop IPC reset lane failed" or "web import indexing failed", not just "the whole pipeline failed".

04 / Domains

Domain Ownership: Fewer Secret Hallways

The ownership reset made "legal import" and "good architecture" closer to the same thing. The important pattern is public surfaces first, internals second.

Area What Changed Why It Matters
Assistant Extracted stable surfaces into packages/assistant-contract, including runtime data, local LLM contracts, provider metadata, memory settings, context packing, and tool metadata. UI and app shell can consume assistant contracts without reaching into agent runtime internals.
Indexing Introduced packages/indexing-contract and moved queue/job/provider metadata toward indexing-owned surfaces. @brainstrike/pipeline became a real production owner instead of an unused package. File import, embeddings, queue, preferences, DB, and app-shell indexing work now have a clearer coordination layer.
File Explorer Promoted internal slices in packages/file-explorer-ui/src/tree, preview, indexing, and shell, with enforced barrels. New work can land in a smaller write set instead of modifying one giant UI package surface directly.
DB Added package-local architecture ownership tests and split DB concerns around queues, migrations, repositories, search, and schema-facing surfaces. DB remains central, but callers should not casually pierce through implementation layers.
Embedding Worker Split support modules for provider runtime, DB IO, cache IO, scheduling, failures, job payloads, chunk filtering, and stats refresh. The main worker file is now a composition point under the 1,500 LOC threshold, not the only place every embedding concern lives.

ELI15 rule

If another domain wants your data, give it a front door. Do not let it climb through your bedroom window. In code, the front door is a public contract, barrel, registry, or typed API.

05 / Desktop

Desktop Runtime Became A Platform

Brainstrike is local-first and AI-native, so the desktop runtime is not just a wrapper. It owns local execution, hidden renderers, reset/recovery, DB host lifecycle, and IPC.

Typed IPC registry

apps/desktop/src/ipc-handlers.ts is now 69 lines and delegates to domain registries instead of collecting everything in one file.

Renderer-only local AI

Embedding workers and built-in local LLM execution stay in renderer contexts. Main owns lifecycle and IPC; it does not execute the models.

Hidden host lifecycle

Embedding and LLM host renderers are modeled as lifecycle surfaces: startup, ready, active, idle, failed, reset, restart, disposed.

06 / Pipeline

The Proof Pipeline Became Risk-Based

The pipeline now behaves more like a router than a giant on/off switch. It looks at changed files, chooses lanes, checks labels, records proof, and makes full release proof explicit.

Cheap lanes

Docs-only and isolated unit-test changes should stay cheap. They do not select broad web, desktop, embedding, or destructive lanes.

Product lanes

Web work is split into smoke, file explorer persistence, import/indexing, assistant state, settings state, DB startup, destructive reset, and full regression.

Desktop lanes

Desktop work is split into smoke, IPC reset, runtime hosts, DB storage, full regression, and embedding diagnostics.

Full release lane

Workflow, risk-routing, and release-risk changes expand to full proof. That is intentional, visible, and label-routed through ci:full.

Command / Mechanism What It Does Why It Exists
pnpm ci:select Classifies a diff into risk profile, labels, commands, E2E lanes, and timing budget. Deterministic lane selection before spending CI minutes.
pnpm ci:prove Runs the selected proof commands locally and writes machine-readable evidence. CI should double-check; it should not be the first real test.
pnpm ci:verify-proof Checks that the proof manifest matches the current head and required labels. Prevents stale proof from looking authoritative.
ci:unit Runs affected unit tests without coverage on PRs. Fast feedback for routine app/package changes.
ci:coverage-db / ci:coverage-full Runs the heavier coverage gate only when DB/storage/file-system/full-risk surfaces require it. Stops broad coverage from being the default PR tax.

The key pipeline correction from PR #1032

The old unit coverage gate was too broad. The merged coverage split added ci:unit, ci:coverage-db, and ci:coverage-full. Routine source changes can now run affected unit tests without dragging the expensive coverage job along, while DB and full-risk changes still get coverage.

08 / .ci Proof

The .ci Proof System, In Plain English

The proof system is a receipt. It records exactly what local commands were run, against exactly which git commit, with exactly which risk lanes selected. The point is to stop PRs from saying "trust me, I ran it" when the code has moved since then.

Without proof

Someone can run tests locally, then change code, push again, and the PR still sounds like it was tested. CI eventually catches this, but the expensive cloud loop becomes the first reliable source of truth.

With proof

The repo writes a machine-readable file at .ci/proof/latest.json. That file says: "I tested commit X, compared to base Y, selected labels Z, and these commands passed in this much time."

Step Command / Artifact What It Means
1. Select risk pnpm ci:select --base origin/main --head HEAD Looks at the git diff and decides what risk lanes apply: docs-only, web, desktop, DB, indexing, full release, and so on.
2. Add labels ci:unit, ci:desktop, ci:full, etc. The selected labels tell GitHub which cloud lanes to run. If the selector says ci:full, the PR must carry ci:full.
3. Run proof pnpm ci:prove --base origin/main --head HEAD Runs the local proof commands selected for the diff, measures duration, records owners/budgets, and writes .ci/proof/latest.json.
4. Commit proof last .ci/proof/latest.json final proof-only commit This is important: source/config/test/doc changes are committed first. The proof file is committed after the successful proof so it points at the already-tested code commit.
5. Verify proof pnpm ci:verify-proof --base origin/main --head HEAD --labels "..." Checks the manifest is structurally valid, the required labels are present, the tested commit matches the current code state, and no source change happened after proof.
6. PR Sentinel checks again GitHub job: PR Sentinel Recomputes the selected lanes in CI and rejects stale/missing proof or missing labels. This prevents local proof from being a decorative file.
Happy path
commit code-> ci:select-> add labels-> ci:prove-> commit proof-> ci:verify-proof-> push PR
Invalid path
commit proof-> edit source-> push-> PR Sentinel fails
Manifest Field Why It Exists Example Meaning
testedHeadSha Locks proof to the exact commit that was tested. If the PR head changes after proof, the proof is stale.
selection.files Records which changed files caused the risk selection. Workflow files usually select full release risk.
selection.labels Lists required PR labels. A ci:full selection requires the PR to have the ci:full label.
selection.commands Records what local commands were required. Docs-only may require only diff checks; full-risk includes full local suite.
commandResults Records pass/fail, duration, budget, and owner per command. Useful for proving not just green/red, but also cost.

The subtle bit: proof is intentionally a separate commit

That feels odd at first, but it is the core invariant. The source commit says "this is the code." The proof commit says "the previous code commit was tested." If another source commit appears after that, the proof no longer proves the current PR head.

10 / Cost

What This Did Not Magically Solve

The reset creates a better system, but it does not erase the cost of a full release-risk change. It makes that cost visible and less frequent.

Full release proof is still expensive

When workflow or risk-selection code changes, the correct answer is still ci:full. That is why PR #1032 ran the broad fan-out.

Risk rules are manual policy

Turbo can run affected tasks, but it does not know product risk by itself. The repo still needs explicit mappings for reset, indexing, desktop hosts, and destructive lanes.

Some compatibility cleanup remains

The legacy ci:coverage token still exists as a compatibility/deprecation surface. Active routing now uses ci:coverage-db and ci:coverage-full.

Honest tradeoff

This system is more precise, but precision has maintenance cost. The way to keep it from becoming brittle is fixture coverage: each new product risk must have selector tests proving both positive selection and negative non-selection.

11 / Next

Next Practical Moves

These are not big rewrites. They are the next small things that keep the new architecture honest.

Next 1-2 PRs

Measure routine PRs against the new lane system

Collect actual wall time for normal docs, UI, DB, desktop IPC, and file explorer PRs. The system should prove savings on routine work, not only on synthetic reports.

Small cleanup

Deprecate or document legacy ci:coverage

Either remove it after updating docs/agent instructions, or document it as a compatibility alias that is intentionally not emitted by current risk profiles.

Ongoing rule

Require selector fixtures for every new lane-relevant surface

Whenever a new product area appears, add risk fixtures that prove it selects the right lane and does not select unrelated expensive lanes.

Architecture hygiene

Keep composition files thin

ipc-handlers.ts, embedding worker composition, file explorer shell, and assistant wrappers should stay orchestration points. If they start growing again, split earlier.
