Next 3 Top Goals

Turn the Architecture Reset Into a Release Candidate

Why first: the branch is already full-release-risk. More refactor before integration increases merge cost and review risk.

  • Rebase or merge-update against current origin/main once, then stop moving the base until the release-candidate proof finishes.
  • Produce a branch-level release note that maps the 156 commits into three review sections: pipeline, ownership, desktop platform.
  • Run exactly one explicit release proof after the base update: selected full-risk commands plus full local suite if still required by ci:select.
  • Resolve the proof-manifest policy: either final proof-only commit for PR path, or no proof artifact for a local-only integration path. Do not leave ambiguous stale proof state.

Cut DB and Indexing Proof Cost in Half

Why second: the pipeline is now measured, and the measured bottleneck is DB/indexing. The slowest normal command is DB at p95 4m 30s.

  • Split DB tests into schema/migration, repository, queue, search, and integration lanes with separate budgets.
  • Move more orchestration behavior from app-shell background indexing toward @brainstrike/pipeline where ownership is already established.
  • Reduce workspace-collection-sync-service.test.ts and related indexing tests into focused owner-owned specs.
  • Target p95 DB/indexing local proof under 2m 30s without hiding failures behind broad mocks.

Make Local AI Operations Product-Grade

Why third: the platform exists; now it needs operating guarantees for the next one to two years of local models, indexing load, and crash recovery.

  • Add a resource scheduler across embedding, chunking, and LLM hosts so GPU/CPU/memory pressure is explicit and observable.
  • Add model artifact lifecycle rules: manifest validation, disk quota, corruption detection, retry policy, and reset integration.
  • Expose host health, queue health, model cache health, and recent recovery events in one product diagnostics surface.
  • Keep recovery E2E lanes under 60s each and never include embedding diagnostics or long soak tests in normal low-risk proof.
