Brainstrike CI Onboarding · 2026-05-24

CI is computed from the diff, not negotiated by humans.

The old local proof manifest and label-routed PR flow has been removed. A pull request now starts with one cheap planner job. That job computes risk, required cloud jobs, and E2E matrices from the changed files. Developers inspect the plan locally, but GitHub recomputes it and owns routing.

Developer Workflow

Step 1

Commit real changes

Source, tests, config, docs, and workflow edits go into ordinary commits.

Step 2

Inspect the plan

Run pnpm ci:select --base origin/main --head HEAD.

Step 3

Run only relevant local work

Use the printed localCommands when local evidence is needed.

Step 4

Open the PR

No CI labels. No generated proof file. No proof-only commit.

Step 5

GitHub recomputes

The PR plan job computes required jobs and dynamic matrices.

pnpm ci:select --base origin/main --head HEAD

What Changed

Old pathNew path
Developer adds ci:* labels.CI ignores PR labels for routing.
Developer runs ci:prove.Developer inspects ci:select and runs targeted local commands only when useful.
Developer commits .ci/proof/latest.json.No generated proof artifact exists.
PR Sentinel validates label/proof state.Required PR Gate validates the exact jobs selected by the plan.
A missing label can waste a failed run.The workflow computes required jobs directly from the diff.
Do not reintroduce the old ceremony. A small PR should not need manual CI labels, a generated manifest, or a proof-only commit.

Research Basis

The replacement follows documented platform behavior instead of label timing. GitHub Actions supports using one job's output to define a later matrix with fromJSON; it also supports job/workflow concurrency and explicit workflow syntax gates. Turborepo's documented --affected behavior remains useful for package-level unit work, but E2E product risk still needs domain-owned lane mapping because E2E tags are product contracts, not package graph outputs.
