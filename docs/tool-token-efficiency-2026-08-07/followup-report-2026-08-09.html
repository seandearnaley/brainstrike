Two waves later: the format waste is gone, and context finally has a lifecycle

Follow-up to the 2026-08-07 audit against opencode, Cline, and Hermes. Twenty-three PRs merged across two waves re-ran the comparison in our favor: every format-level finding is fixed, both systemic gaps are closed, and on several dimensions we now hold the strongest position of the four agents.

01 — Verdict, revisited

Both systemic findings from the audit are resolved in code

The audit's core claim was that our budgets were peer-grade but the bytes inside them were not, and that nothing ever left our context. As of today: every model-facing projection is compact plain text (grep, reads, shell, symbols), the ~180-char per-match grep envelope is a ≤100-char enforced ratchet with the real figure far lower on typical paths, and context now has three subtractive mechanisms — stale-read rewriting, recency pruning, and agentic conversation compaction — all shipped, all built on one durable overlay seam with rollback.

Just as important: the follow-through respected the audit's own rulings. We stayed in the small-page lane (window scaling is capped at 2× the anchor), cost accounting still comes exclusively from provider-reported usage, and where Cline guesses chars/3 for estimation we now measure the estimator against provider actuals per run, per model — Hermes' receipts-first habit applied to the one number everyone else hardcodes.

The file header prints once per file (prefixed by root name only when several folders are open), rows are line: text, warning flags appear only when they actually fire, and the line number doubles as the startLine for a follow-up read. Context lines are opt-in. The same 6,000-char page now carries roughly 4–5× the information, which is the audit's projected win realized — fewer follow-up calls, and every avoided call skips a full-conversation replay.

Reads and shell went through the same conversion: file pages are plain gutter-numbered text with a one-line header and cursor footer (the 11-key JSON envelope and its double-priced newlines are gone), and executeCommand emits exec exit=0 1.2s + verbatim streams with benign exits interpreted (grep exit 1 = "no matches") so the model doesn't burn a turn misreading them. A decoded-length ruler ended the double-charging of newlines everywhere — the same read page that measured as 54 rows under the old ruler carries 100 today.

04 — What "better" bought us

The audit asked for canonical + innovation tokens. Here's where they went.

Most of the two waves was deliberate convergence on formats the three peers already proved. The innovation budget went to four places where our architecture allowed something none of them have:

A durable history lifecycle, not an in-memory one

#2333 · #2355 · overlay table + replay processor
  • Cline's rewriting and opencode's pruning live in process memory and reset per task. Ours is a durable overlay: rewrites and prune markers survive reload, replay deterministically, and roll back (superseder-presence checks; rewinding past a prune self-heals).
  • One seam, three consumers — stale-read rewriting, recency pruning, and M2 compaction all commit through the same table and reset the same caches.

Spill files that are actually a database

#2350 · durable artifacts + search
  • Peers spill to /tmp and hope the model greps it with a different tool. Our artifacts are thread-scoped, cursor-controlled, and now searchable in place — with the scan window decoupled from the projection budget so one search call covers what paging needed ~130 calls for.
  • The delegate hint appears only when a delegation tool is actually registered — no advertising capabilities that don't exist.

Measured calibration instead of a guessed constant

#2356 · calibration pairs + lens
  • Cline hardcodes chars/3 as insurance. We persist (estimate, provider-actual) per run per model — with the denominator fixed to the final step's prompt so the ratio isolates estimator error from step count — and will tune from the distribution, per model, with receipts.
  • Cost display never touches the estimator: provider-reported usage remains the only cost authority, pinned by regression tests.

Window scaling that survives model switching

#2349 · replay-safe scaled budgets
  • Hermes scales budgets but persists nothing, so it never faces the hard case: a projection written under a 200k model replaying into an 8k local run. We accept stored projections at the ceiling tier while fitting fresh ones to the resolved budget — scaling without breaking a single stored thread.
  • Personas resolve budgets from their pinned model, not their parent's — the anti-thrash bound follows the model that actually reads the result.
05 — What review caught

Six would-have-been production bugs died in review

Every PR ran the full bot-review gauntlet (~50 substantive threads in Wave II; each fixed or declined with reasoning, replied, resolved). The ones that mattered:

  • A cancel or a bad API key could shred conversation history. Compaction's summarizer-failure handler was unconditional, so pressing Stop mid-summary — or a 429, a socket reset, an expired key — committed a deterministic truncation of the oldest turns. An invalid key would have done it on every turn until noticed. Now only non-retryable summarizer evidence triggers the fallback; transient failures and aborts leave history intact.
  • The compaction summary would have eaten the previous turn on reload. The summary row was persisted without topology, so history hydration never closed the open assistant group and rendered the entire prior turn inside the compaction card. The test suite missed it because its fixture thread ended on a user message.
  • Prune markers inviting repeated mutations. The first pruning pass could tell the model to "re-run the tool" for a delete or shell command. Pruning now works from an explicit read-only allowlist; mutating and interactive tools are never pruned (their projections are tiny anyway).
  • Artifact-spilled results silently disabling pruning. {type:'json'} projections — exactly the largest outputs — threw inside the size walk and permanently disabled pruning for the thread. Now measured with the serialized ruler; unknown shapes still fail loudly.
  • Calibration measuring the wrong thing. The first pass compared a once-counted estimate against cross-step-summed provider tokens, so the ratio tracked step count. The denominator ruling (final-step prompt) is what makes the dataset usable at all.
  • Small-window models hard-failing on legal pages. Scaling the central assertion below what producers enforce would have killed ordinary reads on Ollama/LM Studio runs. The assertion floors at the anchor until the producers are threaded (BST-1219).

Two E2E regressions were root-caused rather than retried, and both turned into permanent guards. Renderer bootstrap SQL carrying schema mutation tripped the desktop's destructive-schema IPC guard and blocked the assistant panel from mounting — the third occurrence of that bug class, and the fix restored the architectural rule (main-process migrations are authoritative; renderer bootstrap never mutates schema) while adding a unit test that runs the real bootstrap SQL through the real guard. Separately, an Electron launch failure traced to main-process code importing a renderer-only package whose exports map has no require condition; the fix moved the dependency rather than widening the exports map, and added a test that esbuild-bundles the actual main entry points and resolves every external import. Both classes now fail in unit tests instead of costing an E2E cycle.

The remaining distance

BST-1200 M2

Agentic conversation compaction

shipped #2375

The last structural gap vs all three peers, closed. Estimator trigger at ~90% of usable input targeting ~70%; prune-first on the milestone-1 seam; fixed section schema (Goal / State / Decisions / Next / Files) fed only projected transcripts; a deterministic non-LLM fallback on provider overflow that fires only on non-retryable summarizer failure — a user cancel or a 429 leaves history untouched for the next turn to retry; the summary persists as a tagged message with proper topology; the thread shows the compaction point visibly; rewinding past a compaction self-heals by the same presence-gating rule as pruning, with no new coupling in the tombstone machinery.

From: Cline's trigger/fallback discipline + opencode's prune-first ordering + Hermes' cache resets — on our overlay seam.
BST-1219

Resolved budgets threaded into desktop text projectors

shipped #2373

Window scaling now reaches the purpose-built desktop projectors, so the scale-up half is live on large-window models and the anchor-floor stopgap is gone from the fresh-path assertion (replay still validates at the ceiling tier). The persona case became a per-call budget context rather than a construction-time capture, so a pinned small-window subagent fits to its own budget rather than its parent's. Calibration samples now carry the resolved budgets, letting the lens segment by effective tier.

From: #2349's own documented deferral, plus three review findings that proved the floor could only come off once every producer honored the resolved value.
