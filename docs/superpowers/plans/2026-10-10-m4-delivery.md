## Ownership and finite verification

- One owner covers child/client behavior; one covers derived history/retrieval.
  Shared protocol/Main edits transfer explicitly between them. The integrator
  performs removal after their replacement behavior passes. No concurrent
  deletion beneath feature work and no micro-fix ticket or agent proliferation.
- Before edits, map existing tests and M3 receipts to every acceptance row and
  freeze the commands/platforms that must run. Build once per relevant source
  tree. Reuse passing proof only where source, emitted artifacts and runtime
  match; do not launch a redundant baseline campaign.
- Each shared failure family gets one predefined diagnostic invocation, then one
  coherent correction and one complete affected-family retest. Record five
  competing hypotheses with supporting/refuting evidence before a further fix.
  A failed retest stops autonomous patching for a consolidated root-cause
  disposition. New symptoms, workers or platforms do not reset that budget.
- Use the existing child/CLI integration suites as one grouped selection; use
  state projection, deletion/artifact, indexer, SQLite lens/grep and app-query
  suites as the other. Run the existing delegated, search, host-relaunch and
  reset app cases as one locked batch across smoke and regression. Preserve
  assertions, original deadlines and zero retries.
- After composition/removal, run the complete existing local regression and
  required platform/package checks once on the final candidate, followed by
  hands-on app smoke. Collect every failure before deciding a shared correction.
  Do not restart full regression after each leaf; any further broad run needs
  an identified changed boundary. Exhausted budgets do not waive red results.
- At most four local agents including the integrator, with one heavy job per
  machine. No PR status-comment stream. Report completed outcomes and new
  actionable facts, not repeated activity summaries.

Elapsed time to accepted delivery is the priority. Every added code change or
run must resolve a named acceptance failure. Prefer reuse or removal; avoid new
mechanisms, unrelated cleanup and unchanged reruns. These are delivery limits,
not permission to weaken product behavior or claim unexecuted tests passed.

Every pnpm invocation sets `pnpm_config_verify_deps_before_run=error` and
`COREPACK_ENABLE_PROJECT_SPEC=0`; unsigned packs set
`CSC_IDENTITY_AUTO_DISCOVERY=false`. No protected-profile access, credentials,
live provider calls, external OAuth, main merge, signing or release is authorized.
CI is disabled due to cost; validation must run locally.
