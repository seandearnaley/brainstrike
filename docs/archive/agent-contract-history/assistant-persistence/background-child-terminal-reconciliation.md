# Background child terminal reconciliation — evidence

Supports `docs/agents/assistant-persistence.md` § "Scoped child stream hydration" and § "DELEGATION LEDGER KIND".

The 2026-09-26 thread debug pack showed three `agent-explore` background tasks fail at 22:00:07 with "No executor registered". Their parent emitted three `subagent.failed` events and kept running, while six child host-run rows from two stream legs remained `running` without child terminal events. The live child panes consequently kept an active Stop control. A later root completion cannot be the settlement trigger: the parent continues to work after the failed tasks.

The desktop run-event writer now reconciles a persisted parent `subagent.failed` immediately, whether it is emitted by the root, a recursive delegated parent, or an independent child continuation. All three writers use the same settlement function. It resolves the current root host leg's owner and turn plus the event host leg's immediate parent node, then requires the event's exact native parent run/tool call/persona, a failed or cancelled terminal task row, and matching child event identity. A continuation event must also name its bound native run: a misattributed event cannot settle an older task in the same child thread and root turn. Only still-running child host legs move to failed/cancelled and receive one terminal event each. A failed task's stored error message becomes the child run error and terminal detail when present. Completed, suspended, active, unrelated-turn and unrelated-root work remains untouched. The live receiver closes the same open invocation when that parent event arrives, preserving partial output as an incomplete child message; sibling receivers continue. The ledger's terminal status reflects failed or cancelled tasks rather than displaying a green completion for an all-failed fan-out. None of these statuses changes the parent turn's own outcome.

Settlement uses the run-critical foreground database operation with one saturated-host retry. Its single SQL statement updates only running legs, so retrying cannot duplicate a terminal. A missing native error message retains any existing child run error. A queued nonterminal child event after settlement can add history but cannot reopen the failed header or replace its terminal verdict.

An answered pause card can remain in the saved transcript after native execution fails. The live receiver marks only an observed task failure/cancellation with a typed terminal code; event derivation retires that message's waiting display while ordinary transport errors preserve pending approval. The error renderer reads its human message. Reload uses the exact persisted child host-run terminal; another run's failure cannot retire the pause. Historical green approval rows keep their original event label, and an Approved badge records the decision rather than successful execution.
