# Foreground query lifecycle ownership

Supports `docs/agents/local-inference.md` § "Foreground query coordination".

Each DB/runtime generation owns one FIFO for cached service selection, initialization and query generation. Closing that generation fences preparation immediately; its public inference signal requests cancellation and the separate inference promise retains ownership until actual queue settlement. Cached-service disposal also retains lifecycle ownership until settlement; non-inference preparation is never joined during physical teardown.

## PR #3447 review — pending disposal retirement

Exact-head review at `762dd772deaf18125ed42f0ff42727594e10c3cb` identified a second physical-lifecycle gap. Warm A, hold its disposal during a model switch, then issue public host Stop: the original owner acknowledged `stopped` while disposal remained pending. The failing control recorded one RED assertion; a failed disposal could then leave the retired generation holding an unreachable cache. This proves false teardown acknowledgment without claiming a native GPU resource leak.

The physical owner now tracks a single disposal promise and retains its service cache until disposal succeeds. Close joins that already-started disposal, so Stop/reset cannot acknowledge completion or start a replacement early. Failure remains explicit, retains the failed promise, and rejects teardown into the existing main host retirement path without another disposal attempt. Stop attaches worker-stop and query-close promises immediately, so an early disposal rejection is handled even while background Stop waits; restart-limit termination joins both settlements and preserves their errors. Model-row reads, preference hydration and lightweight initialization remain excluded from this join.

Public manager controls cover Stop/reset with both disposal success and failure: one disposal call, no early host destruction/replacement, failed teardown retirement, and successful reset followed by a fresh query. The former delayed-disposal reset tests now require disposal completion before replacement and preserve fresh A/B cache reuse. No retry or deadline change is introduced.

## 2026-09-30 — Request cancellation transport

Public manager controls with the real `HostRequestChannel`, renderer runtime and `SimpleEmbeddingService` showed that an aborted active request never signaled its queue operation, and an aborted or timed-out queued request still initialized and inferred. Main now sends an empty typed cancellation envelope carrying only the admitted runtime/request identity. Renderer admission registers the request controller before enqueueing its FIFO operation; the cancellation listener aborts only that exact generation/request. Duplicate, unknown, malformed and superseded notices cannot abort siblings. Lifecycle close clears the generation's request map and mounted-host cleanup unsubscribes both listeners.

Canceled queued requests skip every preparation step. An active model read, preferences read or initialization has no public abort option, so per-request cancellation retains its FIFO ownership through the real awaited preparation, then checks cancellation before submitting inference. It never races or detaches preparation. Active inference combines the request and generation signals through public `AbortSignal.any`; its actual promise remains the FIFO owner until settlement, so cancellation cannot start a valid sibling prematurely. The existing lifecycle fence still precedes request-abort checks, preserving stale-generation errors. Successful delivery preserves the original caller abort reason. A failed notice send rejects that caller explicitly through the channel's existing hook-error handling, without killing siblings or reporting ordinary cancellation as delivered. A present query bridge lacking cancellation rejects admission explicitly; an absent web host bridge remains omitted.

The request deadline remains 60000ms and the physical Stop/shutdown/reset deadlines remain 10000/3000/30000ms. The controls assert skipped queued model reads, held active model-read/initialization ownership, request-specific active signals, valid sibling progress after real settlement, delivery failure, partial capability rejection, strict empty notices, duplicate/stale notices and listener cleanup across Stop/reset. These are controlled public-service tests, not native hardware evidence.

Guards: `embedding-host-physical-stop-ownership.test.tsx`, `embedding-host-shared.test.ts`, `hidden-preload-runtime.test.ts` and `platform/desktop-ipc-channel-contract.test.ts`.
