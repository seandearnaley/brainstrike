## 🎯 What This Skill Does

### Automatic Activation

Claude will automatically use this skill when you:
- Create or edit Mermaid diagrams
- Work with architecture documentation
- Mention flowcharts, sequence diagrams, ER diagrams, etc.
- Ask about diagram syntax or validation

**No need to explicitly invoke it** - Claude decides when it's relevant!

### Key Capabilities

1. **Error Prevention**
   - Applies learned best practices from project experience
   - Quotes labels with special characters automatically
   - Uses proper syntax for all diagram types
   - Removes invalid comments from ER diagrams

2. **Automatic Validation**
   - Runs `node scripts/validate-mermaid.mjs` after changes
   - Reports validation results clearly
   - Explains any fixes applied

3. **Project Standards**
   - Follows BrainStrike conventions
   - Uses existing validation scripts
   - References comprehensive documentation
   - Maintains consistency across diagrams

4. **Context-Aware**
   - Checks existing diagrams for patterns
   - Searches for similar examples
   - Maintains established naming conventions
   - Follows C4 model for architecture diagrams

## 📖 Skill Configuration

### YAML Frontmatter

```yaml
---
name: mermaid-diagram-validation
description: Create, edit, and validate Mermaid diagrams in markdown files.
             Use when working with Mermaid diagrams, flowcharts, sequence
             diagrams, ER diagrams, state diagrams, architecture documentation,
             or any markdown containing Mermaid syntax. ALWAYS validate after
             creating or editing diagrams. Requires mermaid and glob packages
             (already installed).
allowed-tools: Read, Write, Edit, Grep, Glob, Bash
---
```

### Tool Permissions

**Allowed tools**:
- `Read`, `Write`, `Edit` - File operations for diagrams
- `Grep`, `Glob` - Search for existing diagrams and patterns
- `Bash` - Run validation scripts

**Why these tools?**
- Read-only access to examine existing diagrams
- Write access to create/edit diagrams
- Bash access to run validation scripts
- No network access needed (all local)

## 🚀 How It Works

### Workflow Example

```
User: "Create a sequence diagram showing the login process"

Claude (using mermaid-diagram-validation skill):
  1. Checks existing diagrams for patterns (Grep, Read)
  2. Creates diagram with proper syntax
     - Quotes labels with special characters
     - Uses proper participant names
     - Adds clear labels to arrows
  3. Runs validation: node scripts/validate-mermaid.mjs (Bash)
  4. Shows validation output to user
  5. Explains any fixes applied

Output: Valid, tested Mermaid diagram ready to commit ✓
```

### Progressive Disclosure

The skill uses progressive disclosure to manage context:

```
Initial Request
    ↓
Description Checked (trigger words)
    ↓
SKILL.md Loaded (main guidance)
    ↓
Need examples? → Load EXAMPLES.md
    ↓

    ↓
Need deep dive? → Reference docs/mermaid-guide.md
```

**Benefits**:
- Faster activation (loads only what's needed)
- Less context consumption
- Better performance
- Focused guidance

## 💡 Key Features

### 1. Learned Best Practices

Captures hard-won lessons from actual project experience:

| Error Type | Occurrences | Solution |
|-----------|-------------|----------|
| Unquoted parentheses | ~90% of errors | Quote labels: `["Label (text)"]` |
| Invalid ER comments | ~5% of errors | Remove `//` comments |
| Wrong line breaks | ~3% of errors | Use `<br/>` instead of `\\n` |
| Special chars | ~2% of errors | Quote entire label |

### 2. Integration with Existing Scripts

Seamlessly uses project's validation infrastructure:

```bash
# Primary validation (comprehensive)
node scripts/validate-mermaid.mjs

# Single diagram testing (development)
node scripts/test-one-diagram.mjs
```

**Why this matters**:
- No new dependencies
- Same validation as CI/CD
- Team already familiar with scripts
- Consistent error messages

### 3. Project-Specific Conventions

Enforces BrainStrike standards:

- **Naming**: Architecture diagrams use `01-`, `02-`, etc.
- **Structure**: Follows C4 model conventions
- **Location**: `docs/architecture/*.md`
- **Style**: Consistent label formatting
- **Documentation**: Verification notes for assumptions

### 4. Comprehensive Error Coverage

Handles all common Mermaid syntax errors:

✅ Parentheses in labels  
✅ Comments in ER diagrams  
✅ Line breaks in labels  
✅ Special characters  
✅ Cylinder/database node syntax  
✅ Sequence diagram participants  
✅ State transition labels  
✅ Subgraph definitions

## 🔧 Troubleshooting

### Skill Not Activating

**Symptom**: Claude doesn't use the skill when working with diagrams

**Checks**:
1. Is Claude Code version 1.0+?
2. Is the skill in `.claude/skills/mermaid-diagrams/`?
3. Is `SKILL.md` present with valid YAML?
4. Did you mention "Mermaid" or "diagram" in your request?

**Fix**: Be more explicit: "Create a Mermaid flowchart..."

### Validation Script Fails

**Symptom**: Error when running validation

**Checks**:
1. Are you in project root? `pwd`
2. Is script present? `ls scripts/validate-mermaid.mjs`
3. Dependencies installed? `pnpm install`

**Fix**: Run from project root, ensure dependencies installed

### Syntax Errors Despite Skill

**Symptom**: Diagram has errors even with skill

**Checks**:
1. Did validation run? Look for validation output
2. Did Claude explain the issue?
3. Is the error in a new edge case?

**Fix**:
1. Share error with Claude
2. Ask Claude to fix using skill guidance
3. Update skill with new pattern if needed
