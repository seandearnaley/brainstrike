## 🔧 Technical Implementation Details

### 1. parseEmbeddingLoose() - Multi-Format Parser
**Location**: `packages/db/src/repositories/_shared.ts`

```typescript
parseEmbeddingLoose(embedding: unknown): number[] | undefined
```

**Handles these formats:**
- JSON arrays: `"[0.1, 0.2, 0.3]"`
- pgvector text: `"[0.1,0.2,0.3]"` (no spaces)
- pgvector parentheses: `"(0.1,0.2,0.3)"`  
- CSV strings: `"0.1,0.2,0.3"`
- Native arrays: `[0.1, 0.2, 0.3]`
- **Graceful failure**: Returns `undefined` for invalid input

### 2. Batched insertMany() - Parameter Limit Protection
**Location**: Both repository files

```typescript
async insertMany(chunks: FileChunkInsert[]): Promise<FileChunk[]>
```

**Key features:**
- Splits large arrays into **250-row batches**
- Wraps entire operation in **single transaction** (all-or-nothing)
- Maintains same API contract as before
- **Prevents PostgreSQL parameter limit errors** (32k+ params)

### 3. Vector Capability Detection
**Location**: `packages/db/src/db-provider.tsx`

```typescript
// New hook available everywhere
const vectorEnabled = useVectorEnabled(); // boolean
```

**How it works:**
- On database init, probes: `SELECT 1 FROM pg_extension WHERE extname='vector'`
- Exposes `vectorEnabled` flag through React context
- Hook automatically triggers database initialization when first accessed

### 4. Idempotent Operations - Production Safety
**Location**: Both repository files  

**Problem solved**: This error from production:
```
Error: duplicate key value violates unique constraint "file_chunks_pkey"
Key (id)=(bfdd9297-595f-4f0f-b564-b0d33dfac39e_chunk_0) already exists
```

**Solution**: Added `ON CONFLICT DO UPDATE` to all INSERT operations:
```sql
INSERT INTO file_chunks (...) VALUES (...)
ON CONFLICT (id) DO UPDATE SET
  content = EXCLUDED.content,
  content_hash = EXCLUDED.content_hash,
  -- ... other fields
  updated_at = EXCLUDED.updated_at
RETURNING *
```

**Impact**: Re-importing the same file now **updates** chunks instead of failing.

### 5. Database Schema Improvements

## 🐛 Known Issues & Gotchas

### 1. Import Path Requirements
**Critical**: Use `.js` extensions in relative imports:
```typescript
// ✅ Correct - required for Electron module resolution
import { parseEmbeddingLoose } from './_shared.js';

// ❌ Wrong - will break desktop app
import { parseEmbeddingLoose } from './_shared';
```

### 2. Test Environment Configuration
The vitest config uses environment-specific settings:
```typescript
environmentMatchGlobs: [
  ['**/*.{test,spec}.tsx', 'jsdom'], // React component tests
  ['**/*', 'node'], // Everything else
],
```
