## What’s in place

### Deterministic DB + pgvector (Phase 4)

- Desktop requires pgvector and verifies extension registration before migrations.
- Worker (Electron) initializes the chosen model (WebGPU/CPU), claims queue jobs, writes embeddings idempotently with `embedding_set_id` + `embedding_hash`.
- Embedding sets prevent dimension drift (schema, repositories, and SQL search enforce set scoping).

Key files:
- apps/desktop/src/db-main.ts — pgvector bootstrap + migrations
- packages/embeddings/src/worker/embedding-worker.ts — local‑first worker core (claim → heartbeat → embed → write)
- packages/db/src/repositories/file-chunk-repository.ts — SQL/client search, set‑scoped, normalized [0,1]

### Chunking upgrades (Phase 5)

- Streaming chunk production: async generator avoids building large arrays.
- Markdown pre‑pass: keeps fenced code intact; prose goes to sentence splitter.
- Code‑aware separators for recursive boundary selection (exports, declarations, tests, etc.).
- Expanded skip rules: lockfiles/build output/minified maps/binaries (NUL probe)/common vendor dirs.
- Optional token‑true sizing: sampler computes chars/token for dynamic sizing; pluggable `tokenCounter` per model.
- Importer: opt‑in streaming for large files with batched inserts + per‑batch queue enqueue.

Key files:
- packages/db/src/services/chunking-service.ts — streaming, markdown/code boundaries, skip rules, token‑true sizing
- packages/file-import/src/chunking.ts — streaming path for large files, batching + enqueue
- packages/db/__tests__/chunking-service.streaming.test.ts — fences intact, skip rules, large file streaming
- packages/db/__tests__/chunking-service.token-bands.test.ts — token bands for sentence + tokenTrue sizing
- scripts/chunking-benchmark.mjs — memory deltas (aggregate vs streaming)

## Notable design choices

- Search safety: SQL path requires `embeddingSetId` to avoid dimension mismatches; client path tolerates missing sets but may be capped later.
- Distance normalization: cosine uses `1 - (d/2)`; L2 and IP mapped monotonically to [0,1]. We recommend standardizing on cosine for production unless you add matching HNSW indexes per distance.
- Streaming is opt‑in in importer: you can enable for large files without changing default behavior.

## Risks & mitigations

- Vector index coverage: if enabling distances beyond cosine, ensure matching indexes (HNSW/IP/L2) are created and migration‑safe.
- Fallback scalability: consider requiring `embeddingSetId` even in client path when data volume grows (or cap candidate sets).
- E2E headless flakiness: prefer `pnpm run check:headless` in CI or ensure display provisioning; desktop E2E requires a display.
