# Project vocabulary

Use the terminology in current source, accepted ADRs and the relevant subsystem
contract. Root `AGENTS.md` owns task scope and working rules; there is no extra
read-order ritual for external domain-modeling or triage skills.

The conventional root `CONTEXT.md` is the single glossary location if one is
created from owner-approved decisions. Until it exists, do not cite a missing
glossary or silently treat competing synonyms as settled domain language. Verify
current source instead of inferring behavior from dated plans or receipts.

Use defined terms consistently in issue titles, proposals and code. A missing
concept is a vocabulary question, not permission to create another durable ID or
owner. When a proposal contradicts an accepted decision, name that conflict and
obtain the relevant owner decision rather than quietly overriding it.

Related: [issue tracker](issue-tracker.md), [triage vocabulary](triage-labels.md)
and `docs/adr/`.
