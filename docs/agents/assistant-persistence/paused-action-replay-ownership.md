# Paused action replay ownership

Supports `docs/agents/assistant-persistence.md` § "ASSISTANT THREAD PERSISTENCE & RELOAD HYDRATION", specifically "Message identity and reattachment".

On September 25, 2026, a live `brainstrike.manageCanvas` approval in a background-root continuation failed in 14 ms before native resume. The UI pause belonged to assistant ID `uzCHEYP`; its parent edge was backfilled when the user answered. Mastra's later tool-bearing assistant row was `61b3994a-a8b0-4c45-8f5f-810bd60d8d28`, so exact ID equality failed even though both were in the same turn. The persisted tool call was `call_SDU6yFAQUjPH1aerqkA14Kqp` under host leg `run-ae9577cf-59f1-4eff-8adf-f41129ce2fc7`. The failed answer leg `run-28ca9daa-244f-4fa1-b337-8b44f5ade3f7` never entered stream initialization; its terminal snapshot warning correctly left the original suspended turn open.

The stream and Mastra memory each have their own one-shot ID generator. Later native rows of a held root can therefore carry UUIDs while the visible paused message retains its UI ID. The UI locates the exact action data, not an adjacent message, but that ID need not name the final native row. The host resolves this split only when the UI ID has no native row, has a persisted parent edge into the same anchored turn, the tool call has one native owner, the exact host leg recorded the pause, the native run is mapped to that host leg, and the generation has no terminal event for that call. A durable but wrong assistant ID, missing edge, wrong turn/host/native run, reused native tool-call ID, or completed pause still fails. Native snapshot authorization remains the execution guard after replay preparation.

`packages/assistant-data/src/__tests__/assistant-action-replay-prefix.integration.test.ts` covers live approval and typed suspension, plus those identity refusals and an unrelated generation reusing a tool-call ID. The desktop host emits `assistant_admission_rejected` only when an action leg fails before entering stream initialization, allowing the renderer to release its prepared request while retaining the original pending approval.
