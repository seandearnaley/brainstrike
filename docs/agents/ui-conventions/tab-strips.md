# Tab strips — evidence

Supports `docs/agents/ui-conventions.md` § "TAB STRIPS".
Read before changing tab-strip geometry, activation, the close affordance, overflow or the strip's menus.

---

- **2026-09-27 audit (origin/main 450c4280e).** Four strips were measured live with Playwright on a `vite preview` build. Tab heights were 20/24/27/28/33/40px and radii 0/4/6px; font weights differed between strips, and the Git tabs changed weight on selection. axe-core 4.13 `aria-required-children` failed on the assistant and workspace tablists (close buttons were owned by the tablist); Radix Library tabs passed.
- **Automatic activation reloaded workspaces.** Arrow roving in the assistant strip called `openThreadTab`, and `ThreadWorkspaceCoordinator` keys its hydration on `activeThreadId`, so each arrow press reloaded a saved workspace. This is why activation is manual everywhere (D3).
- **React registers `onWheel` passively**, so the old `preventDefault` in the assistant strip's `onWheel` never took effect. The strip now uses a native non-passive listener.
- **`<Activity>` is not a free keep-alive.** A hidden `<Activity>` unmounts effects. `assistant-ui-panel-wrapper.tsx` subscribes to tool updates in an effect, so root thread panels stay `hidden`-mounted. Child conversations deliberately use `<Activity>` (#3292).
- **`useSyncExternalStore` updates always render blocking** (react.dev caveat), so a zustand-driven tab switch gains nothing from `startTransition` or `<ViewTransition>`. There is no sliding indicator.
- **`onMenuOpenChange` exists for native views (BST-1837, for BST-1840).** The browser pane draws an Electron `WebContentsView` above the renderer, so a Radix menu opened from its strip paints behind the page unless the host occludes the view while any strip menu (tab, strip background or All-tabs) is open.
- **`statusLabel` may stand alone.** Thread tabs carry an identity mark that draws its own badge, and their "finished, unseen" state has no `TabStatus`; the accessible name still needs the text, so it is `statusLabel ?? default text for status`.
- **Sources:** `docs/superpowers/research/2026-09-27-tab-controller-vendor-research.md`. Spec: `docs/superpowers/specs/2026-09-27-unified-tab-controllers-design.md`.
- **Review round on PR #3345 (2026-09-28)**:
  - **Keyboard menu key.** The ContextMenu key opens the menu on KEYUP. Chromium's `WebFrameWidgetImpl::HandleKeyEvent` raises Windows' native page menu on that key's keyup. Shift+F10 stays on keydown.
  - **Pointer focus.** Focus from a pointer never scrolls a tab into view, so a drag doesn't start under a moving tab. The mount reveal jumps instead of animating.
  - **Trackpads.** Horizontal-dominant wheel input stays native, which keeps trackpad momentum.
  - **Focus fallback.** The tablist is the `tabIndex=-1` focus target of last resort.
  - **Per-item reorder.** `reorderable` came from BST-1839, whose child-conversation tabs sit in the scroll group but must not move.
  - **Close All scope.** `closeAll` receives the invoking id so an app strip can scope Close All to one placement group.
  - **Declined:** Codex's "tab stop should follow roving focus". APG Tabs says focus entering the tablist lands on the ACTIVE tab.
- **Pointer close focus (PR #3350 review).** The old thread controller focused the next tab after a ✕ close. The primitive at first did nothing, because the ✕ never takes focus: closing the active tab unmounted its panel, and focus in its composer fell to `body`. A pointer close now refocuses only LOST focus, so focus that survives the close (another panel's input, the browser pane's address bar) stays put.
- **Library panels behind `TabPanelBoundary` (BST-1849, 2026-09-27).** The three Library switcher panels (Threads, Collections, Prompts) in `agent-sidebar-panel.tsx` were the last surfaces spec §7.3 named but did not yet wrap — closing that gap. Each boundary sits inside its `TabsContent`, singleton and unkeyed, so "Reload tab" is the only reset. The Prompts panel's activity-aware content is a callback the parent used to invoke directly in its own render body (for a synthetic "isActive" signal predating any boundary); moving that call into a small `PromptsTabContent` component inside the boundary contains a construction-time throw, but also defers the call to first activation like the other two panels — an existing unit test asserting the pre-activation call was updated to match.
- **Tab chords, closed-tab history and ⌘K tab commands (BST-1842, 2026-09-27).**
  - **Electron menu.** The template in `apps/desktop/src/main.ts` (Application: about/quit; Edit; View: ⌘K, ⌘P, ⌘R, dev tools, zoom, full screen; Developer) plus `application-file-menu.ts` (File: ⌘O, Open Recent) has no `close`, `fileMenu` or `windowMenu` role and no W accelerator, so ⌘W already reaches the renderer and no override was added. Spec §9 said the default `close` role needed overriding; it was corrected. `tab-chords.desktop.test.ts` asserts the menu shape in main, because a CDP key press never reaches a native accelerator.
  - **Capability.** The router claims ⌘W, ⌘⇧T and Ctrl+Tab only when `window.desktopLifecycle` is present: the app, not a browser, owns the window's lifecycle. It replaced `isDesktopRenderer()` (`window.electronAPI`, a platform check) for tab chords; the Terminal's ⌘T hotkey still uses `isDesktopRenderer()`.
  - **Scope.** The workspace registers no panel: it is the strip for focus in no other panel. Browser pane chords work only while focus is in renderer DOM (its strip or URL bar); a focused `WebContentsView` page never delivers keys to the renderer.
  - **Recording.** Each strip diffs its store's order around a close, so every path (✕, Delete, menus, All-tabs Close All, chords) records exactly what closed. A bulk close pops lowest index first so consecutive reopens rebuild the order. Twenty entries per strip.
  - **Staleness.** Dropped and reported: a deleted thread; a workspace app no longer registered; a file whose folder is no longer connected; one entry per reopen. A file deleted from disk under a connected folder is NOT caught first: there is no platform-neutral existence probe (the web adapter's `exists` always answers false, and the content loader stores a missing file as inaccessible content), so it reopens into the tab's existing not-found surface.
  - **Browser pane reopen** recreates the tab at its URL at the END: the bridge has no reorder operation (spec §8.3).
  - **Factory reset.** Each history is component state that dies with its strip, and both reset paths reload the renderer (`factory-reset-panel.tsx`), so no resetter is registered.
  - **Focus after a chord.** Closing the active tab unmounts the focused element, and cycling or reopening hides the panel that held it (found live: Ctrl+PgDn from the composer switched threads once, then focus fell to body and the next press cycled the workspace). Lost focus returns to the strip's selected tab, else its tablist, so the next chord still acts on that strip. Focus sitting inside a `hidden` panel counts as lost: Chromium moves focus off a newly hidden element only at its next rendering step, after animation frames run (traced live: the panel hid at +18 ms, the refocus frame ran at +18 ms with the composer still focused, focusout came at +32 ms).
  - **⌘K.** The palette captures the scoped strip at open, before focus moves into the dialog. Go to Tab… is a `PageCommand` (`Command = RunCommand | PageCommand`); the composer's "/" menu drops page commands.
  - **Web E2E.** Switching threads hydrates that thread's saved workspace (BST-1268), so the assistant-scoped case cannot assert that the workspace strip stayed put; the unit suite pins exclusivity.
  - **Reopen Closed Tab everywhere, empty history benign (follow-up round).** Each strip background menu gained "Reopen Closed Tab" (spec §6.4) through `createReopenClosedTabAction`, enabled only while that strip's history has an entry; the ⌘K command is hidden under the same rule (`TabCommandStrip.hasClosedTabs`). An empty history is `NO_CLOSED_TAB_OUTCOME`, a success with an informational message: ⌘⇧T shows it as a plain toast, like a menu action's success message, and logs nothing at error level. Before this, an empty-history ⌘⇧T logged an error and bumped the diagnostics error chip.
  - **Review round (2026-09-28).** Every strip operation settles through one normalizer, so a synchronous throw or a rejection becomes a reported failure, never an error escaping the keydown listener; `activate`/`close` return promises that settle when done (the browser pane awaits main), and the chord restores focus only after that. `reopenLastClosed` drops an entry only when the strip confirms it stale (a deleted thread, an unregistered app, a disconnected folder); an unloaded thread list, a throw or a rejection keeps it. Chords never act, and never `preventDefault`, with focus inside a modal dialog (`[aria-modal="true"]`: the palettes now declare it, since cmdk's `Command.Dialog` forwards no attributes), an alert dialog or an open menu. ⌘W/⌘⇧T match by `event.key`, falling back to `event.code` only for a non-Latin letter (Dvorak's KeyW is ","; ⌘, is Preferences). A duplicate strip registration logs instead of throwing inside `useEffect`. Go to Tab… items are keyed by tab id with a detail hint (a file's relative path, a page's URL). `getFocusRoot` lets the panel-less workspace take focus back after a ⌘W.
  - **The workspace history is per workspace session.** The thread workspace coordinator swaps the workspace tab set per thread through `hydrateTabs`/`hydrate`; each stamps a fresh `hydration` identity and the provider clears its closed-tab history on it, so ⌘⇧T in thread B never reopens thread A's file. A hydration is a replacement, not a close, and is never recorded.
  - **Real Chrome keeps Ctrl+PgUp/PgDn (Windows/Linux) and ⌘⌥←/→ (macOS)** for its own tab switching, so on web those chords may never reach the page; the web E2E's CDP key presses bypass that. The bindings stay (harmless, and some browsers pass them through); the ⌘K tab commands are the reliable web path.
