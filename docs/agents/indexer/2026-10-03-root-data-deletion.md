# Whole-root data deletion ordering

Rule: desktop delegates whole-root data deletion to the same main owner that captures native authority and retires its sources. Native cleanup acknowledgment and physical retirement precede canonical PG deletion. Cleanup failure preserves PG and retains the original reservation for explicit retry.

The shared shell previously ran its raw PG root cascade before the filesystem adapter disconnected the root. The visible desktop filesystem bridge now supplies `deleteRootData(rootId)` through its existing role/frame-validated contract; shared UI awaits it and propagates failure without invoking its web PG path. The renderer supplies no path, collection, bindings or native port. Web retains its supported ID/path cascade.

The registry captures the actual mounted object synchronously and rejects late borrows/read/mutation admission, including during failed cleanup. Its existing serializer checks the captured object after already-admitted mutations settle. A capture failure before cleanup releases its reservation; deletion refuses while an earlier native transition still owns admission. The main service serializes competing reconfigure/rebuild/reset transitions, captures `captureAcknowledgedAuthority()` before source stop, joins admitted source/read/inference work, then consumes that same owner's final actual native-ACK inventory. It removes only bindings carrying the captured root ID under its actual workspace scope. Every removal ACK precedes physical native writer/profile retirement and PG cascade. A failure retains the phase and original owner; retry does not reacquire current settings/grants or repeat completed PG deletion. Successful resume occurs after releasing the root serializer, so startup can restore remaining roots without deadlock.

The canonical root cascade lives beside existing managed-cache policy and reuses its cancellation helper. It locks exact ID/path identity, cancels only actual rooted chunk jobs, clears queued/running leases and records canceled lifetime metrics, then cascades the root and refreshes affected collection statistics atomically. Membership may be nullable; no collection or root identity is invented.

Causal tests hold source retirement and native ACK ahead of real PGlite deletion, exercise source/native/writer cleanup failure, changed mounted/native owners, final late acknowledged bindings, explicit retry and failed reopening. An actual built native SQLite host and secure mounted temporary directories prove rooted removal plus preserved rootless/other-root/other-collection coverage after reopening. Real PGlite tests prove cross-membership job cancellation, unchanged unrelated leases and rollback of cancellation/cascade together on PG failure. These focused proofs do not qualify the full application or M3, and launch no GPU/model execution or hosted CI.
